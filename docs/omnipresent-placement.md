# 无处不在：初始敌人放置

本地项目从破碎像素地牢 v4.0.2 完整源码快照建立，原始来源为 https://github.com/00-Evan/shattered-pixel-dungeon/tree/v4.0.2 。英烈原有修复代码没有迁入。

第十项挑战的中文名称为“无处不在”，英文沿用英烈 T4 的 Approaching Infinity。英烈的内部倍率为 1000，本实现按需求采用 100。

## 当前实现

- 仅改普通楼层生成时的初始放置，并登记开关与中英文说明。
- 目标数量为原初始数量乘以 100，实际数量不超过合法候选格数。
- 使用普通房间和 TunnelRoom 走廊自身的 `canPlaceCharacter` 规则；房间的重复权重不会重复生成同一格。
- 不在入口房间、特殊房间、特殊地面 `EMPTY_SP`、上下楼梯、不可通行或实体格、陷阱、植物以及已有怪物所在格放置。
- 保留破碎原有入口八格视野与八格步行距离检查，没有扩大保护半径。
- 大型怪物只能放在 `openSpace` 格子。若没有可用的大型位置，则在有限的生成预算内继续尝试其他怪物。
- 每格最多一个怪物。合法位置用完后结束，不通过随机找格的无限重试来追求数量目标。
- 未修改怪物属性、行动时间、寻路、后续刷新、掉落或 Boss 战斗逻辑。

入口保护不是仅靠排除楼梯一格实现的：破碎的入口房间属于 StandardRoom，原始生成还使用入口视野与距离检查。此实现明确排除入口房间并保留这两项检查。

## 验证

- 使用 JDK 11 与项目声明的 libGDX 1.14.0 等依赖，编译 SPD-classes、services、core 共 1305 个 Java 源文件通过。
- 在离线构造地图上实际调用放置方法及 `RegularLevel.createMobs()`，九类场景各四十个随机种子通过：100 倍目标、容量填满、特殊格过滤、狭窄位置与混合大小怪物、仅大型怪物且无大型空位、零可用格、已有怪物、挑战关闭、挑战开启。
- 原版开关关闭时，第一层初始放置仍为八个；启用时，同一测试地图放置八百个。
- 原始生成测试走了入口视野与寻路距离代码。验证工具存放在父工作区 `.research/shattered-placement/`，没有编入游戏。
- 尚未进行 Android 打包或满地图战斗性能测试。本次只验证初始放置，不能据此宣称满载回合、动画和存读档已经稳定。

本地 Git 保存源码改动；没有 Git push。

- 使用本机 JDK 25、Gradle 9.5.0、Android SDK 36 / Build Tools 36.0.0，执行 `:android:assembleDebug` 成功；只配置 Android 所需模块。APK 签名验证通过，安装于 `emulator-5554`（Android API 36，x86_64）。
- 包名 `com.shatteredpixel.shatteredpixeldungeon.indev`，版本 `4.0.2-INDEV`。未增加游戏内作弊或测试功能。备份偏好设置后仅将 `intro=false` 跳过固定教学图，语言通过菜单切换为简体中文。
- 普通随机第一层：挑战掩码 0，11 只怪物，位置无重叠，移动正常。挑战局为另一随机种子，数量用于验证功能，不能当作同种子的精确倍数对照。
